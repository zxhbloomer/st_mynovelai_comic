# 花漫画 1.2.0 漫画阅读器需求

日期：2026-10-12
状态：需求整理，尚未开始实现。本文记录本次新需求，不代表功能已交付。

## 1. 版本与范围

本次较大功能从 1.2.0 开始；实现时统一更新扩展与服务端插件的 package.json、manifest.json。后续围绕本版本递增 1.2.x。

新增独立漫画阅读器，参考现有图片查看器的视觉样式，但不把原有图位历史版本查看器直接改成阅读器。现有图片、预设和历史数据保留，不在本次全面迁移浏览器存储。

## 2. 阅读入口

- 楼层按钮排列：花漫画 │ 清空图片 │ 阅读漫画 │ 下拉。
- 右下角全局悬浮按钮同样增加“阅读漫画”。
- 楼层入口打开对应楼层；全局入口优先打开当前聊天最后阅读的故事楼层。
- 没有漫画时打开空阅读页，提示“本楼层暂无漫画”，仍显示“花漫画”。早期“没有漫画就报错”的描述以本规则替代。
- “花漫画”始终显示，无论当前楼层有没有漫画。
- 尚无阅读进度、原阅读楼层被删除、当前聊天没有故事楼层时的具体回退规则待明确，不能跳到其他聊天。

## 3. 故事楼层定义

故事楼层指酒馆角色发出的回复楼层，不按故事语义再次判断。截图示例：角色回复 #134 算故事楼层，用户消息 #133 不算。

- 从当前聊天数据读取，排除用户消息、系统消息、注释和独立旁白。
- 保留正文非空的角色回复，包括开场白。
- 不按角色名称、日期或当前 DOM 是否渲染筛选。
- 不以是否已有漫画作为楼层资格条件。
- 使用当前选中的消息分支，不把同一消息的其他分支或图片重画历史作为新楼层。
- 展示真实酒馆楼层号；上一/下一楼层按筛选后的顺序跳转，跳过用户等非故事消息。

依据：本地 SillyTavern 1.19.0 public/script.js 的角色消息字段，以及 public/scripts/slash-commands.js、system-messages.js 的旁白与注释类型。官方参考：https://docs.sillytavern.app/for-contributors/writing-extensions/ 和 https://docs.sillytavern.app/usage/st-script/ 。

## 4. 阅读弹窗布局

- 居中大标题：花漫画-阅读，章节：XXXX，楼层：XX层。
- 漫画居中，两侧上一张/下一张箭头。
- 漫画下面显示当前整层剧情简介，翻图不改变简介。
- 显示“当前第 X 张 / 共 Y 张”；无图时显示空页与0张状态，不出现无效页码。
- 底部为故事楼层跳转 toolbar；“花漫画”建议固定放在底栏右侧，始终可见。
- 右上角 X 关闭。
- 阅读图片按楼层正文中的图位顺序读取，每个图位显示当前选中的有效图片；不将同一图位的历史重画版本重复计为漫画页。
- 新窗口复用已有图片记录读取能力，兼顾 IndexedDB 预览及聊天中已保存图片地址的恢复方式。

## 5. 导航与键盘

- 左右箭头及键盘左右方向键：上一张/下一张。
- 当前楼层第一张再向左，进入上一故事楼层最后一张。
- 当前楼层最后一张再向右，进入下一故事楼层第一张。
- 遇到无漫画的故事楼层，显示该楼层空阅读页，不跳过它。
- PageUp/PageDown：上一/下一故事楼层；进入后的图片位置建议第一张，最终规则待明确。
- Esc：关闭当前弹窗；有输入或确认子弹窗时应先处理子弹窗。
- 输入文字、输入楼层号或生成要求弹窗打开期间暂停阅读导航快捷键；避免触发酒馆原有方向键换分支行为。
- 故事列表头尾没有目标时停止导航，不循环。

### 5.1 ST-Chat-Jumper 参考范围

参考 D:/game/sillytavern/tools/github/ST-Chat-Jumper-main 的紧凑工具栏样式、楼层输入、范围检查和导航交互，适配本阅读器，而非整体移植该插件。

建议底栏：上一故事楼层 │ 楼层号/章节选择 │ 下一故事楼层，支持快速跳转。

原插件 jumpToMessage 会滚动聊天页面，showFloorRangeImpl 会 replaceChildren 后重建聊天区间。新阅读器的跳转只更新阅读窗口，不调用其重建聊天页面的区间显示，不改变后台聊天滚动位置，不复制消息编辑/删除/换分支功能。

输入非故事楼层的处理、章节选择控件的具体形式待明确；不得直接按楼层号加减代替故事楼层导航。

## 6. 章节、简介和提示词

- 章节标题、简介是楼层级数据，不是每张图片独立的数据。
- 简介由 LLM 根据本轮漫画规划及完整图片描述生成，不要求额外识图；②③建议沿用同次漫画规划请求。
- 翻图、单张小铅笔改写或重画不更新整层简介；整层重新生成时更新。
- 自然语言提示词由用户写入“提示词模板”中可启用的提示词组，不能把生成简介的自然语言要求写死在代码里。
- 代码只负责约定格式的提取、保存和展示。
- 建议格式为 image 块之外的 chapter_title、chapter_summary；标签方案尚未最终冻结，不能自动给用户预设添加提示词。
- 历史图片没有章节/简介时显示缺失状态，不自动发起额外付费请求。
- ①使用工具结构，若纳入阅读与简介生成，需明确相应字段方案；不能认为文本标签可直接兼容①。

供用户自行填写的提示词建议（非内置默认）：

```text
在完成本楼层所有漫画页的规划和图片描述后，
根据本次漫画实际呈现的事件，额外输出一次：
<chapter_title>简短章节标题</chapter_title>
<chapter_summary>本楼层剧情简介</chapter_summary>
标题和简介放在所有 image 块之外，不属于绘图提示词。
简介使用中文，约80～150字，概括整层主要事件，
不要逐张介绍图片，不加入正文和漫画规划中没有的情节。
保留原有漫画输出格式。
```

## 7. 存储

用户确认不将数据放入 public/scripts/extensions/third-party 下扩展安装目录的 db。

新增章节、简介和阅读进度保存为服务器端本地 JSON，沿用酒馆当前用户文件目录：

```text
SillyTavern-1.19.0/data/default-user/user/files/
├─ HuaManhua_Assistant.json
├─ HuaManhua_NovelDraw.json
└─ HuaManhua_Reader_<聊天标识>.json  # 建议新增命名，具体安全标识待实现确定
```

- default-user 是当前示例，实现必须使用当前酒馆用户，不写死用户目录。
- 阅读数据独立保存，不混入 API 配置或生图预设。
- 按聊天隔离，记录章节、简介、必要图位引用和最后阅读楼层。
- 只要求恢复到楼层，不持久记录第几张漫画。
- 定位需兼顾楼层号变化和消息分支；稳定标识细节待设计。
- 图片本体保留现有图片文件保存方式，不在阅读 JSON 中重复保存 Base64。
- 不全面迁移现有 IndexedDB 图片历史、待交付任务记录或 localStorage 配置。

### 7.1 已核实的现有存储

现有数据并非全在 IndexedDB：core/server-storage.js 和 storage-file.js 已通过 /api/files/upload 保存用户 JSON；gallery-cache.js 保存浏览器图片缓存和版本；draw-common.js 将已保存图片信息写入 message.extra.xiaobaixDrawSaved 并保存聊天；图片经酒馆图片接口落盘。最近20条生成要求使用 localStorage，后台交付恢复记录另有 IndexedDB。

## 8. 花漫画与整层重新生成

阅读器和楼层按钮的“花漫画”均支持整层重新生成。

- 有图位、图片或已保存的漫画描述时先确认；不能只看有没有成功显示图片。
- 建议确认文案：
  “本楼层已有漫画，是否重新生成？重新生成将清空本楼层现有图片及描述，并按本次要求重新生成。取消将保留现有内容。”
- 确认按钮：“重新生成”/“取消”。
- 确认后打开现有“本次生成要求”弹窗；取消该弹窗仍不删除旧内容。
- 用户提交后检查任务状态，正在生成时禁止直接清空。
- 清空图位、对应图片记录和描述，以及旧章节标题/简介，再重新规划和生成。
- 清空失败就停止，不能继续生成。
- 不能仅调用现有函数：现有②③遇到已完成漫画会直接返回，缺图时只补图；新手动入口需明确执行清空后的新一轮生成，不误改变自动配图或补图恢复行为。
- 阅读窗口显示进度，每张图片成功交付后刷新；部分成功显示可用图片和错误，全部失败显示空页和错误。
- 当前阅读楼层变化时，生成完成结果必须更新所属楼层，不能覆盖另一楼层画面。
- 沿用现有图位清空范围，不自动删除服务器上的旧图片文件。

## 9. 实现前尚需明确

1. 阅读器是否覆盖①模式，以及①章节/简介输出方式。
2. 章节/简介的最终输出标签、缺失标题显示规则。
3. 无阅读进度或进度目标丢失时全局入口的回退楼层。
4. PageUp/PageDown进入目标楼层的默认图片位置。
5. 输入非故事楼层时提示还是转到相邻故事楼层；章节选择的最终控件形式。

## 10. 验收要点

- 角色回复参与导航，用户/系统/注释/独立旁白跳过；未生成漫画的角色楼层仍能打开。
- 两类阅读入口、关闭、箭头、快捷键、跨楼层首尾翻页工作一致，不改变酒馆聊天页面。
- 简介切图不变，章节与阅读进度保存后刷新可恢复，不串聊天。
- 预览与已保存图片可读取，当前版本与历史重画版本不混计。
- 重新生成两次取消均不删除，提交才清空；清空失败不生图，生成失败有反馈，成功后刷新。
- 提示词内容由用户配置；缺失简介不偷偷调用 LLM。
- 自动检查、模拟浏览器验证、真实酒馆验收分别记录；真实上游调用和发布不由需求文档自动授权。
